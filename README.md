# Контроллер умного дома

Сервис для мониторинга состояния умного дома: принимает данные от датчиков, сохраняет их и предоставляет API для
взаимодействия.

## Структура проекта

```smartHome/
├── api/

├── cmd/
│ ├── server/

├── internal/

```

## Возможности

- Поддержка двух типов датчиков:
    - **ContactClosure** сухие контакты (датчик протечки, переключатель на замыкание или размыкание). Обычно события
      приходят при изменении состоянии датчика. Например, при открытии двери или окна.
    - **ADC** аналоговый вход (термометры, датчики уровней). Обычно события приходят при изменении показаний датчика.
      Например, при изменении показаний датчика температуры или влажности.
- Хранение данных:
    - In-memory (deprecated)
    - PostgreSQL (production)
- REST API для управления данными
## WebSocket API

Сервер предоставляет единственный WebSocket-эндпоинт для получения событий в реальном времени:

```/sensors/{id}/events```

## API Endpoints

Основные эндпоинты:
- `GET /ping` - проверка работоспособности
- `POST /sensors` - создать датчик
- `Post /event` - создать событие
- `Post /user` - создать пользователя

Полная документация доступна `/api/swagger.yaml`


## Требования

- Go 1.20+
- PostgreSQL 14+
- Docker (для тестов и развертывания)


## Установка

1. Клонировать репозиторий:
   ```bash
   git clone https://github.com/MVenjoyer/SmartHome
   cd smartHome
   ```
2. Установить зависимости:
   ```bash
   go mod download
   ```

## Подготовка окружения

1. Поднимите контейнер командой:
    ```bash
   docker-compose up -d
   ```
2. Для миграции нужно выполнить команду
    ```bash
    migrate -path=./migrations -database postgres://postgres:postgres@127.0.0.1:5432/db?sslmode=disable up
    ```
3. Также к проекту приложен Makefile, с помощью которого тоже можно выполнить миграцию

    ```bash
    make migrate-up
    ```

## Запуск

```bash
   go run cmd/server/main.go 
   ```

## Запуск тестов

Тесты в процессе запуска используют docker. Убедитесь, что он у вас запущен.

1. зайти в терминале в каталог с домашним заданием
2. вызвать ```go test -v ./... -race```
